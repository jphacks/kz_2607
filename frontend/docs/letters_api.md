# 手紙画面の接続仕様

## バックエンドへの依頼

手紙は、そのユーザーが「一番最初に作った1体」だけを対象にします。
現在の `getLetters` は `createdPets` 全件の手紙を返しているため、次の対応をお願いします。

1. `users/{uid}/createdPets` の作成日時が最古のpetIdを特定する。
   同日時の場合も対象が変わらないよう、petIdなどで順序を固定する。
2. 最初の子の手紙だけを抽出してから、新しい順・最大30件にする。
3. 戻り値に `firstPetId` を追加する。引数なし、リージョンは従来の `asia-northeast1`。

```json
{
  "firstPetId": "最初に作った子のpetId",
  "letters": [
    {
      "letterId": "手紙ID",
      "petId": "最初に作った子のpetId",
      "petName": "ミロ",
      "title": "旅先からの便り",
      "body": "手紙本文",
      "generation": 3,
      "createdAt": "2026-10-25T00:00:00Z"
    }
  ]
}
```

- 最初の子がいない場合：`firstPetId: null, letters: []`
- 最初の子はいるが手紙がない場合：`firstPetId: petId, letters: []`
- 名前未設定の場合：`petName: null` を許容
- 非認証・他ユーザーの手紙は既存の認証・権限チェックで拒否

フロントはこの形式に対応済みです。最初の子のpetIdは手紙の新旧から推測しません。
`firstPetId` なしで手紙が返る場合は、本文を表示せず
`getLetters / reason: first_pet_id_missing` をエラー詳細に表示します。
空の配列のみの旧応答は、手紙なしとして表示できます。

## フロントの範囲

- 手紙タブから一覧・本文表示
- 起動時の取得、更新ボタン、引き下げ更新、エラー再試行
- firstPetIdに一致した手紙だけ表示
- 読むだけ。返信・既読保存・通知登録は今回の対象外
- Firestoreへの直接アクセスはしない

このブランチは見守る画面が入っていない基点から作られています。
既存の4タブ構成を維持して手紙だけ追加しています。見守る側の3タブ変更を
取り込む際は、手紙への導線をこのLettersScreenへつないでください。
